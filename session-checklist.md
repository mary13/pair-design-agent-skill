# Pair Design Session Checklist

Use this checklist to set up, run, and wrap up Pair Design sessions effectively.

---

## 🚀 Pre-Session Setup

**Before starting design work:**

### Preparation
- [ ] Clear block of time available (minimum 30 minutes for meaningful progress)
- [ ] Design problem identified and scoped
- [ ] Relevant context/research gathered
- [ ] Decision template accessible
- [ ] Quick reference visible

### Role Assignment
- [ ] Synth role assigned (usually human)
- [ ] Gen role assigned (usually AI)
- [ ] Both parties acknowledge the Pair Design agreements
- [ ] Role swap conditions understood (if applicable)

### Problem Framing
- [ ] Design problem stated clearly
- [ ] User needs/context shared
- [ ] Constraints identified (technical, business, time)
- [ ] Success criteria defined
- [ ] Scope boundaries set ("in scope" vs "out of scope")

### First Step
- [ ] First artifact/screen identified
- [ ] Starting point agreed upon
- [ ] Approach direction confirmed
- [ ] Questions clarified before generation begins

---

## ⚙️ During Session - Continuous Checks

**Run through these checks periodically during the session:**

### Agreement Compliance (Every Iteration)
- [ ] **CRITICAL:** Only one artifact created per iteration
- [ ] Work shown immediately (not accumulated)
- [ ] Rationale provided with each artifact
- [ ] Feedback requested before proceeding
- [ ] Decisions made before moving forward

### Gen (AI) Checks
- [ ] Asking clarifying questions when uncertain
- [ ] Presenting options (not single solutions)
- [ ] Explaining design rationale
- [ ] Waiting for synth feedback
- [ ] Not assuming requirements

### Synth (Human) Checks
- [ ] Giving specific, actionable feedback
- [ ] Making timely decisions (not deferring indefinitely)
- [ ] Keeping focus on current artifact
- [ ] Preventing scope creep
- [ ] Catching agreement violations

### Quality Checks
- [ ] User needs addressed
- [ ] Design patterns consistent
- [ ] Rationale sound and documented
- [ ] Trade-offs understood
- [ ] No red flags triggered

---

## 🚨 Red Flag Monitor

**STOP immediately if any of these occur:**

- [ ] ⛔ Multiple screens/artifacts dumped at once
- [ ] ⛔ Major architectural change without discussion
- [ ] ⛔ Work proceeding without feedback
- [ ] ⛔ Requirements assumed instead of confirmed
- [ ] ⛔ Scope expanding beyond agreed focus

**If red flag triggered:**
1. Stop the current action
2. Acknowledge the violation
3. Review the relevant agreement
4. Correct course and continue

---

## 📊 Per-Artifact Checklist

**For each screen/wireframe/component created:**

### Before Generation
- [ ] Clear what artifact is being created
- [ ] Purpose/goal of this artifact understood
- [ ] Context from previous artifacts considered
- [ ] Any special requirements noted

### During Review
- [ ] Artifact serves its intended purpose
- [ ] User needs addressed appropriately
- [ ] Design patterns applied consistently
- [ ] Rationale makes sense
- [ ] Trade-offs are acceptable
- [ ] Technical feasibility confirmed

### Feedback Loop
- [ ] Specific feedback provided (not "looks good" or "I don't like it")
- [ ] Changes requested are actionable
- [ ] Priorities clear (must-fix vs nice-to-have)
- [ ] Understanding confirmed before revising

### Before Moving On
- [ ] Current artifact approved
- [ ] Decision documented (if significant)
- [ ] Pattern noted (if reusable)
- [ ] Next artifact identified
- [ ] Direction for next step clear

---

## 📝 Documentation Checkpoints

**Documentation should happen throughout, not just at the end:**

### Ongoing Documentation
- [ ] Decision ID assigned and tracked
- [ ] Context captured while fresh
- [ ] Rationale recorded as discussed
- [ ] Alternatives noted when considered
- [ ] Patterns identified and named

### Decision Documentation Triggers

Document when:
- [ ] Choosing between multiple viable options
- [ ] Establishing a new pattern
- [ ] Making a trade-off
- [ ] User feedback changes direction
- [ ] Technical constraint influences design
- [ ] Business requirement shapes UX

---

## 🎯 Mid-Session Progress Check

**Every 30-60 minutes, pause and check:**

### Progress Assessment
- [ ] Moving at steady pace (not too fast, not too slow)
- [ ] Agreements being followed consistently
- [ ] Decisions getting made, not deferred
- [ ] Documentation keeping up with work
- [ ] Quality maintained throughout

### Energy Check
- [ ] Both roles engaged and collaborative
- [ ] Feedback loop healthy (not adversarial, not rubber-stamping)
- [ ] Work feels focused (not scattered)
- [ ] Momentum maintained (not stalled)

### Recalibration (if needed)
- [ ] Adjust pace if too fast/slow
- [ ] Refine scope if drifting
- [ ] Take break if energy flagging
- [ ] Review agreements if violations occurring
- [ ] Realign on goals if losing focus

---

## ✅ Session Wrap-Up

**At the end of the session:**

### Work Review
- [ ] All created artifacts reviewed one final time
- [ ] Completeness check (what we set out to do vs what we did)
- [ ] Quality check (meets standards and requirements)
- [ ] Consistency check (patterns applied uniformly)

### Documentation Completion
- [ ] All decisions documented
- [ ] Decision IDs sequential and accurate
- [ ] Rationale captured for each decision
- [ ] Affected files/screens listed
- [ ] Tags and metadata added

### Patterns & Learnings
- [ ] Reusable patterns identified and named
- [ ] Components documented for future use
- [ ] Best practices noted
- [ ] Pitfalls/anti-patterns recorded

### Artifacts Organized
- [ ] Files named consistently
- [ ] Folder structure clean
- [ ] Links/navigation working
- [ ] Version controlled (git committed)

### Next Steps Identified
- [ ] What's complete
- [ ] What's in progress
- [ ] What's next (prioritized)
- [ ] Any blockers or dependencies noted
- [ ] Next session scope defined

---

## 📈 Session Retrospective

**Brief reflection to improve future sessions:**

### What Worked Well
- [ ] Which agreements were easiest to follow?
- [ ] What made collaboration effective?
- [ ] Which patterns emerged naturally?
- [ ] What accelerated progress?

### What Could Improve
- [ ] Which agreements were violated (and why)?
- [ ] Where did we get stuck?
- [ ] What slowed us down?
- [ ] What would we do differently?

### Action Items
- [ ] Specific improvements for next session
- [ ] Process tweaks to try
- [ ] New patterns to explore
- [ ] Documentation adjustments needed

---

## 🎯 Success Indicators

**A successful session shows these signs:**

### Process Quality
- ✓ One artifact per iteration (no dumps)
- ✓ Every artifact reviewed before proceeding
- ✓ Decisions made promptly
- ✓ Documentation complete and current
- ✓ Agreements followed consistently

### Output Quality
- ✓ Artifacts serve intended purpose
- ✓ User needs addressed
- ✓ Design patterns consistent
- ✓ Rationale sound and documented
- ✓ Trade-offs understood and acceptable

### Collaboration Quality
- ✓ Roles clear and respected
- ✓ Feedback specific and actionable
- ✓ Both parties engaged
- ✓ Work feels collaborative, not directive
- ✓ Steady progress maintained

---

## 🔧 Common Issues & Quick Fixes

| Issue | Quick Fix |
|-------|-----------|
| Too many screens at once | "Stop. Show me just the first one." |
| Vague feedback | Use formula: "Change [X] to [Y] because [reason]" |
| Can't decide | "Which is easiest to change later?" |
| Losing focus | Review scope and success criteria |
| Documentation lagging | Pause generation, catch up on docs |
| Moving too fast | Enforce one-at-a-time rule strictly |
| Moving too slow | Set timer for decisions, trust iteration |
| Scope creeping | Create "parking lot" for future ideas |
